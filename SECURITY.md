# Security Policy

## Reporting a security vulnerability

Please do **not** disclose security vulnerabilities, exploit details, credentials, private keys, enrollment tokens, API keys, customer data, or other secrets in a public GitHub issue.

If GitHub shows **Report a vulnerability** for this repository under the **Security** tab, use that private reporting channel.

If private vulnerability reporting is not available, open a minimal public issue that contains **no vulnerability details or sensitive data** and ask the maintainers for a private reporting channel.

For ordinary product bugs that do not expose sensitive security information, use the structured **Bug report** issue form.

## What to include privately

When reporting a security issue through a private channel, include only what is needed to reproduce and assess the issue:

- affected Data Relay Link version
- affected component and platform
- concise impact description
- minimal reproduction steps
- relevant logs with secrets removed
- suggested mitigation, if known

Please avoid submitting live credentials or customer data even through a private report when a redacted reproduction is sufficient.
